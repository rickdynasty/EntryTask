# 根内容宿主重命名与占位清理

日期：2026-10-25。根据用户确认保留单宿主结构，只明确职责与清理无引用占位，不改四Tab业务、认证、网络或存储逻辑。

## 当前结构与命名

```text
MainActivity：认证、Native底栏、根宿主协调
└── shell/host/RootContentHostFragment
    ├── RN模式：唯一ReactFragment / EntryTask Surface → 四个RN Route
    └── Native模式：ComposeView → NativeDashboardRoute → 四个Screen及独立页面VM
```

旧名HomeFragment容易被理解为仅首页；新名表示四个Tab共同的内容宿主。单RN instance与单Fragment不是同一概念；本次保留原有单宿主/单Surface设计，没有为Tab另建实例或Surface。

## 为什么增加FragmentFactory

FragmentManager保存的状态含有Fragment类全名。只删除旧类而修改引用，新安装可能正常，但旧状态恢复会找不到`com.entrytask.home.HomeFragment`。

[RootContentFragmentFactory](../../android/app/src/main/java/com/entrytask/shell/host/RootContentFragmentFactory.kt)处理：

1. MainActivity在`super.onCreate`前安装该Factory。
2. 收到旧宿主完整类名时，将待实例化名称映射为新RootContentHostFragment。
3. 委托原RNScreensFragmentFactory实例化；RN Screens自身的恢复处理保持。
4. FragmentManager继续处理原有saved state、tag和子Fragment，不用null状态或丢弃整个恢复状态绕过问题。

旧类名仅作为映射字符串和测试输入保留，不保留旧实现类或typealias。未使用的三个占位Fragment不是当前根宿主恢复路径，不将它们全部映射成根宿主，以免恢复出多个根实例。

继续保留：

- 外层tag：`entrytask-root-hub`。
- 外层容器：`R.id.fragmentContainer`。
- RN子层tag：`entrytask-rn-root`，容器：`R.id.rn_content`。
- Native视图ID：`R.id.native_dashboard`。
