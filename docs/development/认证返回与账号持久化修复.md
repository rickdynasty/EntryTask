# 认证返回与账号持久化修复

日期：2026-10-22。范围：Android Native登录/注册、认证Mock与SP账号记录；不修改RN、iOS、Codegen、包名或单ReactHost约定。[决策](../adr/013-auth-back-and-mock-persistence.md)。

## 问题与核查结论

1. AuthActivity 原返回回调在收键盘后直接finish，后台singleTask MainActivity会恢复。原Shell设计允许取消后挂载门禁/公开帮助，与本次“登录根页不得返回首页”的用户交互不一致。
2. 旧认证Mock用contains判断路径，用户名直接拼入JSON；包含引号等字符可使响应无法解析。注册只覆盖同一对SP键，因此第二个账号会替换第一个。用户名被trim，密码逐字比较；两次异步apply也不是一次确认落盘的账号提交。
3. MainApplication仍删除更早版本mock_db用户名/密码，无法为完整旧账号保留迁移机会。当前mock_reg键未被该启动清理删除，不能把所有重启失败都归因于启动清理。
4. Repository/VM已存在Toast机制。错误文案依赖返回码：401对应凭证不符、409对应已注册；不能以手拼JSON或错误码类型不一致造成的解析失败冒充凭证错误。修复不直接把服务端/底层异常文本展示给用户。

以上是可复核缺陷及回归场景；未获取用户实际账号密码，也不据此声称已复现该账号的每次历史失败。

## 返回交互

| 场景 | 行为 |
| --- | --- |
| 登录页IME可见 | 先收键盘，重置退出计时，不关闭认证页 |
| 登录页首次返回 | Toast“再按一次返回键退出应用”，认证页和后台MainActivity均保留 |
| 2秒内再次返回 | 清除内存会话并递增epoch、清除退出结果载荷，finishAffinity关闭整个应用任务，不强杀进程 |
| 超过2秒或进入后台 | 重新从第一次提示开始 |
| 注册页系统返回 | 由Compose导航返回登录，不露出MainActivity |
| 点击“直接登录” | 清注册页密码/请求，回到登录，重置退出计时 |
| 认证成功 | 建立Native会话，setResult携带原flowId，finish当前AuthActivity，回到同一MainActivity |
| 系统移除/程序性取消 | 保留原MainViewModel的Canceled与重入协调，不无条件循环拉登录 |

Repository提交会话前检查协程取消及发起时epoch。双击退出后即使认证请求迟到返回成功，也不能重新写入会话或产生成功导航；已在Mock落盘的注册记录不因客户端取消回滚。

认证页的计时器属于当前Activity，不使用BackPressHelper的全局点击时间。登录Composable的BackHandler确保根页不会被NavHost/Activity默认返回弹出。注册页由NavHost处理返回。

设备回归发现Android的finishAffinity不能携带Activity Result数据，首次实现因此失败。现已只在退出整个任务的分支清除结果数据后再退出，并保留正常登录成功的关联编号。

## 注册、重启、登录的数据链路

```text
表单 → 独立UserViewModel → UserRepository → UserService/Retrofit
    → NetManager/OkHttp后台线程 → MockInterceptor
    → manifest精确POST /api/user/register或/api/user/login
    → MockAccountStore → SharedPreferencesAccountStorage → app_default_pref
    → 分API成功JSON或共享错误模板 → Native数字业务码 → Repository会话/VM Toast
```

- 注册：读取/迁移旧记录 → 按用户名查重 → 计算盐和密码校验值 → 一次commit确认落盘 → 从register JSON构造完整响应 → Repository建立Native会话。
- 重启：UserAuthManager内存会话归零，但账号SP保留；启动不再删除旧账号键。存在账号记录不能自动视为已登录。
- 登录：同一端口重新读取SP → 对输入密码按记录算法/盐计算 → 常量时间比较 → 匹配才返回login成功模板并建立内存会话；不匹配返回业务401。
- 新注册账号互不覆盖；同用户名重复注册409，不修改原密码。注册/登录用户名trim且区分大小写，密码不trim、不做静默大小写转换。
- 空字段/超过边界（用户名256、密码1024字符）返回400；原页面空值先做本地校验。边界是当前实现，不能把设计稿的1～32/1～64目标描述为已落地。
- 普通Mock延迟修正为1000～3000ms，短片后台等待并检查取消；不访问真实Socket，不更换请求通路。

## SP格式与迁移

文件仍为应用私有 `app_default_pref`，没有为RN暴露任意键读写。

| 项目 | 当前实现 |
| --- | --- |
| 新键 | `mock_auth_v1.<SHA-256(trim用户名)>` |
| 新值 | `v1:<算法>:120000:<16字节salt的hex>:<32字节verifier的hex>` |
| 算法 | 优先PBKDF2WithHmacSHA256；Provider不支持时兼容PBKDF2WithHmacSHA1；校验按记录算法，不随设备默认值漂移 |
| 并发 | Store实例共用进程锁，防止并发注册/迁移互相覆盖；昂贵计算和commit在OkHttp后台线程 |
| 旧键对 | `mock_reg_username/password`、`mock_db_username/password` |
| 冲突 | 新版账号不被旧版覆盖；两版旧账号同名时mock_reg优先 |
| 删除时点 | 校验记录写入和完整旧键对删除同一次commit；失败不返回注册/登录成功 |
| 无法恢复 | 缺一半的旧键对暂保留；已被早期版本删除或卸载清掉的账号不能凭空恢复 |

新记录不含用户名原文和明文密码；盐/校验值不是加密后的密码。目标方案中的Keystore封装/Room仍待实施，本次不宣称完成生产安全认证。日志只保留API、requestId、业务码、异常类，不打印用户名、密码或响应载荷。

迁移后旧APK不能识别新键，不能用直接回退APK替代迁移方案；应保留新版读取能力并前向修复。正常退出登录不删除账号记录。

```sh
adb -s emulator-5554 shell am force-stop com.entrytask
```

### 执行过程偏差

首次误用了Gradle connected设备任务；发现其清理会卸载目标应用后停止了该调用。卸载前已临时备份账号SP，重新安装后恢复，并通过文件内容一致性校验。随后全部设备复验使用直接instrumentation。账号SP已恢复；未完整备份其他应用私有文件，因此其他本地数据可能因工具卸载被重置。该测试方式选择不当，不应把它归为应用普通重启行为。临时账号备份不提交仓库，不记录账号内容。
