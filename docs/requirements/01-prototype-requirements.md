- **已明确**：用户本轮明确的约束，作为本期硬边界。
- **图片可见**：静态图可识别的内容，不据此推定已存在真实银行能力。
- **补充默认**：为可执行原型补充的规则，可按本文制定方案；未获得产品确认，不称为已确认业务事实。

本期交付项均为必需项；不将异常态、复用、Native 能力接入或演示说明留到“有时间再做”。真实金融交易、第五个借钱 Tab 和 iOS 编码不属于本期。

## 2. 目标、范围与基线决策

### 2.1 产品目标

交付能够在 Android 演示的混合应用原型：用户先完成 Native 认证，再访问四个 RN 业务域及全部子页面；产品浏览、资产查看、签到、权益领取和消息已读形成一致的本地模拟流程；工程支持 RN 与 Native 两条网络通路；本期 37 个原型 API 默认走 Native Mock，并可观察加载、失败和重试。

| ID | 需求与默认规则 | 来源 |
| --- | --- | --- |
| B-01 | 四 Tab 固定为“首页、财富、会员、我的”，顺序同现有 Android，冷启动默认首页 | 四 Tab 已明确；顺序/默认为现状沿用 |
| B-02 | 截图五 Tab 中的“借钱”不作为第五 Tab；保留“我的借钱”营销入口，进入演示说明页 | 已明确四 Tab + 补充默认 |
| B-03 | Android/iOS 的根容器、底部 Tab、认证入口、系统生命周期与基础能力由 Native 负责；Tab 内部及子页面由 RN 负责 | 已明确 |
| B-04 | 顶部业务栏、分段控件、列表、卡片、按钮、筛选、提示、弹层及子页标题栏优先用可复用 RN 控件；不重复显示 Native/RN 两套标题或底栏 | 已明确 + 补充默认 |
| B-05 | 四个根页和所有业务子页必须先登录；RN通过Native Bridge查询会话并拉起原生认证，取消停留在门禁 | 2026-10-19用户明确要求，替代V1.1游客浏览默认；见[ADR-011](../adr/011-required-native-authentication.md) |
| B-06 | 会话仅进程内有效；应用退到后台再返回保持，进程终止后重新认证；RN重挂载从Native读取会话 | 2026-10-19同步全局门禁；不持久化银行凭证 |
| B-07 | 本期注册成功保留当前自动登录行为，但必须由 Native 建立完整有效会话；不允许只设置登录布尔值 | 补充默认，沿用当前 VM 行为；替代旧文档“注册返回登录”默认 |
| B-08 | 本期无后端、无公网 API 兜底，37 个原型 API 及写操作默认走 Native 网络本地 Mock，普通模式每个请求随机等待 1000～3000ms；工程允许为有明确服务需求的 API 配置 RN HTTP 通路，未配置真实服务不得虚构直连成功 | 已明确 |
| B-09 | RN 不保存银行认证凭证；允许经统一封装的 RN HTTP 通路，接口级策略决定使用 RN 或 Native，不得在页面散落直接请求；持久化仍经 Native，不直接导入业务 JSON 充当数据源；RN 有独立日志门面，核心跨端流程同时关联 Native 日志 | 已明确 |
| B-10 | iOS 仅列出职责、能力契约和未来验收要求；不修改 iOS 工程，不将其能力描述为已实现 | 已明确 |

B-11（已明确，2026-10-18）：应用采用单 RN instance；Tab/页面切换不得新建实例，异常重建须先销毁旧实例。B-12：业务开发前完成根入口、src 分域分层、能力层和共享组件目录整理；网络库/状态库均统一封装、配套边界检查与样板验证，具体见RN方案。

### 2.2 范围等级

- **完整原型（F）**：有可交互页面、数据、异常状态、返回路径；写操作具备可验证结果与重复保护。
- **只读原型（R）**：有列表/详情或摘要，可加载和重试；无资金或真实权益操作。
- **演示说明（D）**：统一 RN 说明页，展示服务名、模拟范围、尚未提供的能力及返回按钮。不能只有无响应按钮或笼统“敬请期待”。

产品和活动详情、签到页、资产等子页是补充默认的原型设计，后续视觉方案应按字段和流程补稿。截图下方未露出的内容不要求凭空复刻。

### 2.3 明确排除

真实开户、绑卡、身份核验、转账、支付、申购赎回、还款、授信、购汇、实物发货、信用卡申请和真人客服；相机扫码、推送、实时行情、外部 H5、短信或生物认证；新增真实后端；完整国际化和深色视觉稿；正式上架配置。相关可见入口仍须按本文提供说明页或只读原型。

## 3. 源码现状与目标差距

| 范围 | 当前静态证据 | 需求影响 |
| --- | --- | --- |
| RN | `App.tsx` 为 NewAppScreen 模板；`package.json` 为 RN 0.86.0/React 19.2.3 | 四域、共享组件、MVVM 和 Native 能力适配均待建设，不据版本字符串断言工具链通过 |
| Android 根 UI | `MainActivity.kt` 有四 Tab/Fragment；`BottomTabBar.kt` 为 Native 底栏 | 保留 Native 根职责，承载 RN 页面并补生命周期、返回和恢复 |
| Android 业务页 | `home/*Fragment.kt` 为文本占位；`BaseFragment.kt` 有 RN 容器分支 | 不能视作 RN 四页已完成，需替换业务内容并验证恢复 |
| 认证 | `biz_user` 已有 Compose 登录/注册、UserViewModel、UserRepository、UserAuthManager | 复用 Native 页面；修正注册布尔登录、会话与 Token 两套状态、退出清理及取消返回 |
| 网络 Mock | `lib_net/MockInterceptor.kt` 识别 login/register，随机休眠，内联 JSON，其余请求放行 | 增加 API 级文件、场景、查询匹配、状态写入、可取消等待和未匹配拦截；禁止公网放行 |
| 存储和日志 | `lib_storage/StorageManager.kt`、`lib_base/.../MLog.kt` 已有工具 | 尚未证明存在 RN 可调用契约；补用户隔离、异步错误、脱敏和跨端一致行为 |
| iOS | `ios/EntryTask/AppDelegate.swift` 为 RN 启动模板 | 未核查到本项目 Native 认证/业务桥接实现，本期不补代码 |

现有 Android 文档中的“业务迁往 Native biz_* 并优先 Compose”“无 RN 页时不新增桥接”“FakeRepository 直接供页面演示”“强制 Room 样板”等不作为本期业务需求。技术方案必须按本文重定边界；不得把旧实施路线照搬到 RN 页面。

### 4.2 导航与生命周期（NAV）

| ID | 规则 |
| --- | --- |
| NAV-01 | Native 是根 Tab 选中状态的唯一来源；RN 跨 Tab 跳转必须同步 Native 底栏，不可只改变内容。 |
| NAV-02 | 已登录根页显示 Native 底栏；未登录门禁和 RN 子页面隐藏底栏。Native 认证全屏展示，成功只关闭认证页并恢复原 MainActivity。Tab 内分段仍属于根页。 |
| NAV-03 | 同一会话内切 Tab 保存各自根页滚动位置和筛选；从子页返回恢复列表位置。子页不提供根 Tab 切换入口；跨域导航按明确目标进入，返回原发起页面。 |
| NAV-04 | Android 返回顺序：关闭 RN 弹层/键盘 → 返回 RN 子页上一层 → 非首页根页切首页 → 首页根页由 Native 按现有双击返回退出规则处理。不得一次点击同时触发 RN 返回与 Native 退出。 |
| NAV-05 | 页面离开取消不再需要的查询、注销订阅；重建不得重复挂载、重复展示认证、重复签到或领取。隐藏 Tab 不持续轮询。 |
| NAV-06 | 配置重建保持有效会话与当前非敏感导航；进程终止重启先认证再回首页，清除旧受保护栈及待恢复动作。RN单独重建依Native快照恢复，不自行推断登录。 |
| NAV-07 | 无效 ID、缺失参数、未知路由显示可返回的错误页；不能空白或崩溃。快速双击同一入口只打开一次页面。 |

## 7. 认证、权限与数据一致性

### 7.1 认证链路（AUTH）

1. 游客点击受保护入口，Native 只打开一个认证流程，记录非敏感目标、来源及一次性请求标识。
2. 登录失败保留认证页并可重试；取消回原 RN 页，不退出应用、不反复拉起认证。
3. 注册由 Native 完成，成功通过与登录相同的完整会话建立流程，再返回原目标；Native 不把密码或 Token 发给 RN。
4. 成功后 RN 获取 Native 会话摘要并刷新个人区块；**只恢复页面导航，不自动签到、领取、转账或发起其他写操作**，用户需再次明确点击。
5. 若目标已失效/资源不存在，返回来源根页并提示；认证请求已消费则不再次跳转。

Native 是会话唯一事实来源。RN 可读取 authenticated、opaqueUserId、脱敏展示资料、会话版本及变更事件，不可收到 Token、密码、Cookie；请求认证注入在 Native 内执行。登录/注册表单仍为现有账号密码，不从截图新增手机号验证码。空账号/密码本地拦截；补充默认账号 1～32 字、密码 1～64 字，账号 trim，密码不 trim；重复账号返回明确业务错误。默认演示账号见配套文档，任何密码仅用于本地模拟验证，不作银行密码规则宣传。

### 7.2 会话失效与跨页同步（DATA）

| ID | 要求 |
| --- | --- |
| DATA-01 | 登录、注册、退出和失效经统一 Native 会话链路完成，RN 挂载/回到前台先取快照再按版本消费事件，不能因漏收事件残留个人信息。 |
| DATA-02 | 当前 Native 银行会话范围内的 HTTP 401 或约定 AUTH_REQUIRED 导致一次会话失效；403/普通业务错误不自动退出；RN独立公开服务的401不影响银行会话。旧会话的迟到 401 不使新用户退出。失效后清受保护栈，回所属根页游客态并提示；用户再点保护入口时认证，不强制循环弹窗。 |
| DATA-03 | 签到/领取/已读成功后，以返回的权威结果更新对应共享数据并使相关摘要失效重取；首页/财富/我的的资产、会员/我的能量、已领权益/卡券数、全页消息角标各自一致。 |
| DATA-04 | 所有个人数据、请求结果和缓存按用户及会话隔离；A 退出后 B 登录不得看到 A 身份、资产、权益和消息；旧响应不得回写缓存。 |
| DATA-05 | 退出清除凭证、个人展示缓存、内存状态和待处理导航；本地 Mock 账号下的签到/领取/已读作为模拟服务端数据保留，重新登录同账号可见。普通退出不等于重置演示数据库。 |
| DATA-06 | 隐藏金额的偏好可通过 Native 普通存储按账户保存；新账户默认隐藏；退出立即清页面明文，切换账户读取对应偏好，不能读取上一个账户值。 |

## 8. 分层、分模块与平台职责需求

这是后续方案必须满足的约束，不预先指定物理目录、库选型和桥接代码。

| 层/角色 | 必须承担 | 边界 |
| --- | --- | --- |
| RN View | 四 Tab/子页渲染、用户交互、可访问性 | 不直接调用 HTTP 库、操作持久化或操作原生单例；不计算签到奖励等权威结果 |
| RN ViewModel | 只读页面状态、用户意图、加载/刷新/提交/错误和结果过期判断 | 不持有 Native UI 对象；不得把多个页面可变状态混为全局大对象 |
| RN 领域/用例 | 确有复用的业务规则与跨仓库流程；不强制每操作建用例 | 不依赖 React/RN 控件或具体 bridge 实现 |
| RN Repository / DataSource | 按域建数据访问契约、模型映射和能力调用；RN HTTP 与 Native bridge 封装集中复用，由接口策略选择 | 不在组件散落 NativeModule 调用，不复制 Native 会话、持久缓存及模拟服务端规则 |
| RN 业务域 | home、wealth、member、profile 责任清楚，跨域用稳定只读契约/路由 | 不互相导入页面私有 VM 或数据实现；公共组件不含某个业务域私有规则 |
| Native 宿主/认证 | 根导航、RN 承载、认证、会话、系统返回和前后台、能力组装 | 不再实现四域业务页面和第二套相同页面 VM |
| Native 技术能力 | 网络传输/本地拦截、存储、日志、安全边界、生命周期桥接 | 通用网络库不硬编码会员奖励/产品路由等域规则 |
| Native 演示业务数据 | 各 API 的 JSON、状态变化、业务日与用户隔离；模拟服务端角色 | 仅演示使用，与通用网络能力分离，RN 不直接访问文件或数据库 |

Android 按业务域和技术职责分层、分模块，Native 认证/宿主继续以 MVVM 落地。RN 同样采用 MVVM：View → ViewModel → 可选用例 → Repository → DataSource → 统一 NetworkPort（RN HTTP / Native 能力）。Native 提供能力不意味着把 RN 页面的全部页面业务搬进 Kotlin；两个端不维护两套同一页面状态。

### 8.1 Native 能力需求（BR）

| ID | 能力 | 最小语义要求 |
| --- | --- | --- |
| BR-01 | 能力协商/宿主上下文 | 获取协议版本、支持能力、当前根 Tab、安全区、前后台状态；关键能力缺失可诊断。 |
| BR-02 | 网络 | 异步请求、取消、超时、HTTP/业务/解析错误区分、请求标识与 traceId；参数受控，不能任意公网 URL；认证与 Mock 在 Native 内完成。 |
| BR-03 | 存储 | 异步读写删、作用域/类型/版本、明确失败；按用户隔离；不开放任意文件路径或凭证 Key。RN 页面暂态可保留内存，需持久化时必须经此能力。 |
| BR-04 | 会话与认证 | 查询快照、订阅变更、打开认证及结果（成功/取消/失败）、退出；不暴露凭证。 |
| BR-05 | 导航/宿主 | 选择 Tab、认证往返、子页底栏显隐、返回消费协调；与 Native 选中态和生命周期一致。 |

| BR-07 | 生命周期/事件 | 可订阅与取消订阅，重复挂载不重复回调；事件含版本/标识，重复事件不重复业务提交；Host 销毁后无悬挂回调。 |

“bridge NativeModule”指功能边界要求，具体使用哪种 RN 原生模块机制及其与当前版本的兼容性由后续技术方案实测确定。业务代码依赖稳定适配接口，不把模块机制扩散到页面。

### 8.2 iOS 后续需求

未来 iOS 须提供与 BR-01～07 语义一致的能力，并实现 Native 认证、Tab 和宿主返回/手势协调；复用同一 RN 四域页面、API 逻辑标识、JSON 字段、错误码及业务日。平台差异仅在能力适配及系统交互，不能在 RN 页面复制 Android/iOS 两套业务流程。后续 iOS 需单独完成 Mock 拦截、存储隔离、日志脱敏、Bundle 故障及前后台验收；本期所有 iOS 运行验收标记“延期”，不影响 Android 文档验收，不宣称双端可运行。

## 9. 网络、Mock、存储与日志需求

### 9.1 网络与 Mock（NET）

- NET-01：RN 请求经统一 NetworkPort；按 API descriptor 明确选择 Native 或 RN HTTP。本期 37 API 默认 Native Mock，完成参数/鉴权/场景匹配、读取随包 JSON、状态变更和响应；禁止静默切换通路或用 FakeRepository 绕过已定义网络流程。
- NET-02：每次实际 Native Mock 业务请求随机等待 1000～3000ms，包括成功、空、业务失败、HTTP 失败、未知接口等常规响应；主线程和 JS 线程不被阻塞。并发请求各自延迟，不能全局串行累计。测量为拦截器配置等待值，端到端耗时允许调度/序列化开销。
- NET-03：超时/取消/桥接参数无效不要求继续等待；超时场景以配置超时触发。自动化允许固定延迟/随机种子，普通演示默认必须随机且在范围内。
- NET-04：按 method + 精确 path 模板 + 规范化 query/body + 场景匹配，禁止 contains("login") 等模糊分支；未知接口返回 MOCK_NOT_FOUND，无公网兜底。相同 API 不同类型/ID/分页需返回相应数据。
- NET-05：按 API 拆 JSON，按场景拆成功/空/失败等数据；业务 JSON 不嵌在 Kotlin/Swift/TS 字符串中。Android 在构建时将对应 JSON/manifest/seed 打入 APK assets，release 不依赖 Metro、开发机路径或远程下载；assets 只读，运行状态存 Native 数据库。可共享 schema/模板，但接口不能共享一份万能响应。
- NET-06：写操作校验当前 Native 会话与业务状态，提交成功才更新本地模拟服务端状态；重复提交不重复奖励/领权益；不把只读 JSON 当作无需状态管理的业务实现。
- NET-07：Mock 无需互联网，正常场景开飞行模式仍可演示；另提供显式网络不可用场景验证错误页。所有业务图片本地提供，避免隐性远程依赖。

详细接口、字段、文件约定及数据场景见配套文档，属于同一需求基线。

### 9.2 存储（ST）

Native 负责模拟服务端状态、业务持久缓存及用户偏好。公开列表缓存默认有效 5 分钟，记录 fetchedAt，过期可先展示带时间旧内容并更新；每个新实际网络请求仍遵守随机延迟。个人资产不持久缓存，登录/重进受保护页按需刷新；会话仅内存。RN 可维护页面内存状态，不能再建第二套落盘缓存。

账号、权益领取、签到、消息已读等本地模拟服务端数据在进程重启后保留，账号间隔离；开发/验收提供独立“重置演示数据”控制，不混入普通用户设置或退出流程。重置需显式确认并清会话/相关缓存，恢复固定种子数据。密码不明文保存、不落日志；已有明文 Mock 密码和旧 Token 的清理/迁移必须纳入方案。存储失败不得显示领取/签到成功；偏好保存失败可保留当前页面选择，但提示未保存。

### 9.3 核心流程日志（LOG）

| 类别 | 必需事件与内容 |
| --- | --- |
| 导航 | Tab 切换、页面进入/退出、跨域跳转；pageId、sourcePageId、目标 ID 的安全标识 |
| 认证 | 认证发起、成功、失败、取消、退出、会话失效；单次 flowId，禁止账号密码/Token |
| 请求 | 请求开始/结束/取消/超时/解析失败；requestId、traceId、apiId、场景名、配置延迟、耗时、HTTP/业务码 |
| 核心业务 | 签到/领取/已读的发起、成功、失败、重复；flowId 关联网络请求，结果 ID 可用非敏感演示标识 |
| 基础故障 | Native 能力缺失、存储失败、RN 加载失败、恢复失败 |

LOG-01：RN 必须有自己的日志入口、分级、模块标签和本地调试输出；Native 调用及核心功能关键节点同时进入关联的 Native 日志。单个 span 只有一个终态，RN 调用 span 与 Native 执行 span 通过 parentSpanId 关联；取消为取消而非业务错误。LOG-02：不得输出密码、Token、Cookie、完整手机号/卡号、明文资产响应、搜索原词或整个请求 body。LOG-03：验收可通过本地调试日志按 flowId/requestId 找到从点击到响应的链路，无需建设外部采集服务或上传日志；日志失败不阻断业务，不允许无限缓存。
