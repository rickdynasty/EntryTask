# EntryTask 原型需求基线

版本：1.1 · 日期：2026-10-18 · 状态：需求评审稿

本目录依据四张PRD图片、当前源码和Android文档初稿，定义后续技术方案的业务输入。本次仅文档交付，尚未实施页面、bridge或Mock数据文件。

| 文档 | 内容 |
| --- | --- |
| [原型需求规格说明书](01-prototype-requirements.md) | 范围、四Tab逐入口行为、页面清单、认证、分层及RN/Android/iOS职责、验收与待评审默认 |
| [接口与Mock数据需求](02-api-mock-requirements.md) | 37个逻辑API、字段口径、按API的JSON文件要求、随机延迟、状态/幂等、场景和种子数据 |

阅读顺序：需求主文档 → API/Mock附录 → 修订工程技术方案。用户明确的本期边界优先：四个Tab及子页采用RN；Native提供认证、宿主框架、网络/存储/日志能力，RN具有自己的HTTP封装和Logger；按API选择网络通路，无后端的37原型API默认Native本地Mock且随机延迟1～3秒、JSON随APK打包；应用单RN instance；业务开发前完成前端结构整理与库封装；Android本期落地，iOS本期不编码。

静态图片之外的签到周期、领取规则、游客范围、会话时效、子页和注册语义等均标记为补充默认，供评审，不伪称图片事实。截图有五个底栏入口，本期采用用户指定的四Tab，并将借钱降为说明入口。

`android/docs` 原有文件是旧技术方案初稿，其中原生业务UI优先、Fake直接返回业务、注册返回登录、强制Room样板等与本期需求存在冲突。旧稿保留供追溯，冲突处以本目录需求为后续方案输入，实施前统一修订，不把旧任务清单直接当本期范围。

技术设计入口：[EtryTask 项目设计方案](../design/EtryTask%20项目设计方案.md)，配套[前端RN技术方案](../design/前端RN技术方案.md)、[Android 技术方案](../design/Android%20技术方案.md)、[iOS技术方案](../design/iOS技术方案.md)。技术设计为待评审目标，不代表已实施。
